# Ashfall 美术资源导入与命名规范

## 1. 交付入口

美术原始文件先放到：

`Assets/Art/_Incoming/<批次名>/`

批次名格式：`YYYYMMDD_内容`，例如：

`Assets/Art/_Incoming/20260907_player/`

这里允许保留美术师原始文件名。不要在 Windows 资源管理器里移动已经被场景、Prefab、材质或 ScriptableObject 引用的资源；完成导入检查后，通过 Unity 编辑器移动并同时保留 `.meta`。

## 3. 通用命名

- 只用小写英文、数字和下划线：`snake_case`。
- 名称顺序：`对象_状态_方向_序号`。
- 不用空格、中文、连字符、括号或特殊符号。
- 不写 `final`、`new`、`最新版`、作者名或日期；迭代由版本管理记录。
- 同类资源使用两位序号：`01`、`02`。单一资源不加 `01`。
- 贴图、Sprite、Prefab、动画和音频的基础对象名保持一致。

示例：

```text
player_drill_idle.png
player_drill_move_side_01.png
iron_intact.png
iron_crack_01.png
iron_crack_02.png
iron_crack_03.png
iron_break_01.png
hub_fuel_station.png
ruin_relay_core_active.png
ui_icon_fuel.png
vfx_dust_hit_01.png
sfx_drill_hit_rock_01.wav
mus_surface_hub_loop.ogg
```

## 4. 类型规则

### Block

项目现有规格为：每格 `128 × 128 px`，`Pixels Per Unit = 128`，Pivot 为中心点，世界尺寸为 `1 × 1 unit`。

每种 Block 最少提供：

```text
<block>_intact.png
<block>_crack_01.png
<block>_crack_02.png
<block>_crack_03.png
<block>_break_01.png
```

如有多帧崩碎动画，继续使用 `_break_02`、`_break_03`。画布尺寸、Pivot、透明边距和轮廓位置必须完全一致。

### 角色与动画

格式：`<角色>_<动作>_<方向>_<帧号>`。

动作建议统一为 `idle`、`move`、`dig`、`hurt`、`dead`、`interact`；方向使用 `front`、`back`、`side`。左右镜像时只交付 `side`，避免重复资源。

动画资源使用：

```text
anim_player_drill_idle.anim
anim_player_drill_move.anim
ac_player_drill.controller
```

### UI

图标：`ui_icon_<用途>`；面板：`ui_panel_<用途>`；按钮：`ui_btn_<用途>_<状态>`。

UI 九宫格图必须预留可拉伸的纯净中间区域。字体文件保留字体官方名称，不擅自重命名字体内部信息。

### 音频

- 音效：`sfx_<对象>_<动作>_<序号>`
- 环境声：`amb_<区域>_<状态>`
- 音乐：`mus_<场景或主题>_<状态>`

循环音频以 `_loop` 结尾。

## 5. 文件格式

- Sprite/UI/VFX：优先 PNG，透明背景使用 RGBA。
- 可编辑源文件：PSD、Aseprite 等保留在对应批次的 `Source/`，Unity 正式引用导出的 PNG。
- 音效：WAV；长音乐和环境循环可用 OGG。
- 不把 JPG 用于需要透明边缘的游戏资源。
- Sprite 图集可以交付，但同一图集只包含同一对象或同一功能组，避免做全项目巨型图集。

## 6. 导入验收

整理进正式目录前检查：

1. 尺寸、透明通道、Pivot 和 PPU 是否正确。
2. 动画各帧画布和角色锚点是否一致。
3. 是否存在重名、近似重复资源和测试图。
4. Block 五个基础状态是否齐全。
5. 资源是否仍被正式场景错误地从 `_Incoming` 或 `Placeholder` 引用。
6. 移动或改名后场景、Prefab、材质和 `BlockVisualProfile` 引用是否完整。

## 7. 推荐工作流

1. 美术将资源放入一个新的 `_Incoming/<批次名>/`。
2. 保留原始名称并提交一份简单说明，注明用途、帧率、是否循环及特殊导入要求。
3. 由项目侧统一检查、重命名、设置 Texture Importer、切图并移动到正式目录。
4. 接入场景或数据资产后做一次 Play 验收。
