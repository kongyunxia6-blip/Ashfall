## 2. 目标架构（DEV-016 统一后的单一权威链）

把「地层（是什么岩层）→ 基底填充（每地层岩石底色）→ 矿物叠加（每地层允许矿）」统一成一条**从代码定义到真实世界**的链，同时保留既有 DEV-001~015 语义层可独立演进：

```
StratumCatalog（DEV-012 既有：6 地层语义/硬度/深度规范）
   └─ 作为「长期地层唯一权威」，补 baseTile + allowedOreIds 落地
DigGrid.Generate()
   1. 每格 y → StratumCatalog.ForDepth(y)        // 判定当前岩层（替代只认矿物的 GetLayerAtDepth 主键）
   2. 填「该地层 baseTile」                        // = 对应 <stratum>_base_intact 的 TileDefinition
   3. (可选空间 pass) UndergroundSpaceGenerator    // DEV-008
   4. (可选矿脉 pass) OreVeinGenerator 读 OreRegionPreset/权威带   // 仅把地层允许矿叠上
   5. (可选遗迹 pass) / (可选 discovery pass)      // DEV-013 / DEV-014 不变
   RefreshAll() → 每格经 visualProfile 取 <stratum>_base / <stratum>_<ore>_intact sprite
```

要点：
- **不改** DigGrid 的坐标/耐久/裂纹/落石核心；只在 `Generate()` 的「基底填充选择」处引入地层判定，作为可选的模式。
- **保留旧模式路径**：DigGrid 上未挂新「地层生成器」时维持 `PickStrata/PickRandom` 现状 → 旧场景/旧回归逐字节零回归。
- **Game.unity 走新模式**：挂载一个 DEV-016 地层填充器 + OreVeinGenerator，正式美术驱动。

## 3. 需要你拍板的决策项（每条给出推荐）

### 决策 1：正式世界的「地层边界」以哪套为准？
- 新美术/展示标签：Soil 0-100 / Normal 100-250 / Dense 250-450 / Granite 450-575 / Basalt 575-700。
- `StratumCatalog`：Soil 0-100 / Normal 100-250 / Dense 250-450 / GraniteBasalt 450-700 / Crystallized 700+（**Granite 与 Basalt 合并为一档 GraniteBasalt**，其内可按子带细分）。
- **推荐**：以 `StratumCatalog`（代码语义，DEV-012 回归锁定）为地层主键；美术 5 文件夹 = 4 个可显示地层（Soil/Normal/Dense）+ GraniteBasalt 的 **granite 子带(450-575)** 与 **basalt 子带(575-640)**。即正式 640m 世界可见 **5 段**（soil/normal/dense/granite/basalt），其中 granite/basalt 同属 GraniteBasalt 层的两个视觉子带。这样不改 StratumCatalog，回归不破，又能让 5 张 `*_base_intact` 全部出场。

### 决策 2：替换 TileDatabase 的「按矿物分层」填充模型吗？
- 现状 `TileDatabase.layers` 以矿物权重混入基底；要「地层岩色」必须改成：基底=纯地层岩石（value==0），矿物全部交给 OreVeinGenerator 叠加。
- **推荐**：DEV-016 为**地层模式**新建独立的基底填充来源（读 StratumCatalog.baseTile 或专用地层资产），**不删不重排**旧 TileDatabase.layers（旧模式仍可用 → 零回归）。TileDatabase 保留给非地层旧场景/测试。

### 决策 3：矿物词表怎么对齐？（美术 24 种 vs 生成 10 种）
- 美术多出且资产已存在但未进生成：coal/lead/amethyst/sapphire/uranium/energy_crystal/ancient_alloy/anomalous_crystal/unknown_mineral。
- 生成层有但美术无图：Iron（深层）/Ashfall 核心矿等。
- **推荐（阶段化）**：
  - **DEV-016 V1**：以「美术已提供的 <stratum>_<ore>_intact」为唯一合法矿图集合，只把**有图**的矿接进对应地层；Iron 仅用 soil_rubble 那张；深层 Ashfall 若无图暂不启用（或回退占位 rock 图）。
  - 需要 Codex 补 **normal/dense/granite/basalt 层的 Iron 图 + Ashfall 核心矿各层图**（若想深层保留它）。
- 请确认：深层铁 / Ashfall 核心矿是否必须保留？若保留，需要 Codex 补美术或先用占位。

### 决策 4：新美术缺 crack/break 帧怎么办？
- 新 PNG 只有 `_intact`。`BlockVisualProfile` 需要完整帧才能出 4 段裂纹。
- **推荐（先跑起来）**：DEV-016 给每个正式块绑定「intact = 正式美术；crack1-3/break = 复用占位 rock/iron 的裂纹帧（或临时调暗）」——保证可玩闭环有裂纹反馈，同时标注 **待 Codex 补各块 crack/break 帧后替换**。
- 请确认是否接受「intact 正式 + crack 占位/调暗」的过渡绑定，还是等 Codex 补齐帧再绑？

### 决策 5：Game.unity 是否启用 OreVeinGenerator + 地层填充器？
- 现状 Game.unity 走散点矿（PickRandom），OreRegionPreset 未用。
- **推荐**：DEV-016 给 Game.unity 挂「地层填充器 + OreVeinGenerator」，矿脉带扩展为跨 640m 的多段（浅=soil 层铁铜锡铅、中=normal/dense 层银金铂宝石、深=granite/basalt 层铀/能量晶/合金/异常），并给 OreRegionPreset 增加能覆盖 640m 的带（或新增地层权重源）。

### 决策 6（交付口径）
- DEV-016 是否同时产出「地层填充 + 矿脉」**两条 Editor 回归**（断言每地层 base 纯填充、矿只落在允许地层、边缘 bedrock 镜像仍在），并要求 Game.unity 手工 Play 一次即可？
